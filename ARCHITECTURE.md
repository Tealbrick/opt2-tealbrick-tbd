# TBD (Tealbrick desktop): architecture

State: verified against the repo on 2026-10-17. Claims cite paths in this repo. Anything not verified is marked UNVERIFIED. For the whole system see the system `ARCHITECTURE.md` and `SYSTEM-OVERVIEW.md`.

## 1. Three aspects

- **Chat** (`chat/`): a React 19 renderer in a WKWebView plus a bundled Node 24 helper over private stdio (JSON lines). The helper holds the person session (`portal.ts`), the agent identity (`agentIdentity.ts`, `signerSocket.ts`), the default agent, the relay launcher, update checks and "Save to Knowledge". The default agent (Claude Agent SDK) and the relay are esbuilt into `out/tbd/agent.mjs` and `out/tbd/relay.mjs`. Model setup supports local Ollama first, then Anthropic.
- **Companion** (`companion/Dayflow`): screen timeline, daily and weekly review, a `dayflow` helper, and an agent write channel (a Unix socket under `~/Library/Application Support/com.tealbrick.desktop/Companion/`, mode 0600, only while "Allow edits" is on).
- **Listen** (`native/`): offline speech to text (Parakeet through FluidAudio, WhisperKit alternative), library (SQLite through GRDB), dictation, meetings, vocabulary, transforms, "Save to Knowledge".

## 2. Identity and credentials

- **Person:** device flow `client_id=tbd`, `scope=owner` gives an owner session (`tbo_`). Stored as keychain item `tealbrick.person`, with user presence where entitlements allow. Reads and drafts only; launches open in the system browser (C16 B4).
- **Agent:** device flow `scope=agent`, `harness=tbd-default`. The Ed25519 K4 key is generated by the native host and kept in the keychain (`tealbrick.agent.<label>`, this device only, when unlocked). **It is a software Curve25519 key, not a Secure Enclave key.** The Chat helper never sees the private key: it talks to a user-only Unix socket that signs only `tb-agent-assert+jwt` inputs for this agent, connection and bridge, lifetime at most 60 s. The relay child runs with an allow-listed environment (`PATH`, `HOME`, signer socket, bridge URL, connection, agent and bridge ids): no person token, no Portal URL.
- **Save to Knowledge** calls `knowledge__document_create` through the same agent identity. Holds are polled with `heldOf` and `pollHold`. The owner approves in Portal.

## 3. Release and updates

`scripts/release.sh` runs only on the release Mac: assemble Release, set `Info.plist` (the updater compares **`TBDReleaseVersion`**, the full semver such as `0.1.0-dev.4`, not the short version), codesign inside-out with Developer ID and hardened runtime, audit every Mach-O (team id, hardened runtime, timestamp, no `get-task-allow`), zip, notarize with `notarytool`, staple, `spctl`, rebuild zip and dmg, write `.sha256`, and with `TBD_PUBLISH=1` create the GitHub release (a tag with `-` is a pre-release).

Updater (`TBDUpdater.swift`, `chat/src/main/updates.ts`): checks every 24 hours, fetches the signed index from the platform repo's `registry` release (`github.com/Tealbrick/opt2-tealbrick-platform/releases/download/registry`; builds from before the move work through GitHub's redirect), verifies it with the pinned release key (the platform registry key, `registry/keys.json` in the platform repo), picks the newest `tbd` desktop entry newer than `TBDReleaseVersion` on the allowed channel (stable; stable and dev for the beta opt-in) whose `minOs` is met. It re-validates the offer, caps the download at 2 GiB, compares sha256, requires exactly one `TBD.app` with a newer version, and requires a code signature with the running app's team id. It installs only after the person clicks. The index URL and key are hard-coded in the app (rotation ships in a TBD update). The feed depends on the platform repo (public) staying reachable.

## 4. Local data (paths from code; the file layout inside each folder is not listed)

TBD v2 has its own identity (C280 C10, C284): bundle id `com.tealbrick.desktop`; `~/Library/Application Support/com.tealbrick.desktop/` (Companion, Listening, Chat helper state; `com.tealbrick.desktop-dev` for the dev identity), the agent workspace next to it in `com.tealbrick.desktop-agent/Workspace` (the data folder stays fully denied to the agent), the agent signer socket in a private `$TMPDIR/tbd-<hash>/` folder (Unix socket paths must fit 104 bytes), `~/Library/Logs/com.tealbrick.desktop`, `~/Documents/TBD Desktop`, UserDefaults `com.tealbrick.desktop`, keychain services `com.tealbrick.desktop.person`, `com.tealbrick.desktop.agent.<con>`, `com.tealbrick.desktop.models`, `com.tealbrick.desktop.chat`, `com.tealbrick.desktop.companion.apikeys`. The archived v1 app (`com.tealbrick.tbd`, `Application Support/TBD`, `TBD Agent`, `Dayflow`) is never read or written; the agent's file policy denies it. Permissions requested: screen recording, microphone, audio capture, calendars, Apple Events. Network: Portal, the bridge, the update feed, model endpoints the person chose, and the `yt-dlp` download on first use (verified against SHA2-256SUMS, not bundled).

## 5. Design

Swift tokens are generated from `@opt2-tealbrick/ui` (`chat/scripts/design-tokens.ts`). `design-guard.ts` fails on new raw colours, fonts and radii; the baseline in `design/guard-baseline.json` can only shrink. `design-sameness.ts` compares Swift and web values.

## 6. CI

`tealbrick-ci.json` kind `desktop`, `paths: ["chat"]`. CI runs the TypeScript part on Linux: secret scan, typecheck, lint, unit, build. The Swift build, signing and notarization run on the release Mac (a written exemption in the platform CI README). There is no GitHub Actions workflow in this repo. Swift tests are not in CI.

They are served from the dist host (mirrored as legacy entries). The planned move to `@opt2-tealbrick/relay` needs the CLI releases first.
